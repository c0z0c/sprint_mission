# 📖 FastAPI: 기본 구조

## 1. FastAPI란 무엇인가
FastAPI는 Python으로 작성된 최신 웹 프레임워크로, **빠른 성능**, **간결한 문법**, **자동 문서화** 기능을 제공하는 것이 특징입니다.  
특히 비동기 프로그래밍(`async`/`await`)을 지원하여 높은 처리량을 보장하며, 타입 힌트를 적극 활용해 코드의 가독성과 안정성을 높입니다.  

### 주요 특징
- **고성능**: Starlette와 Uvicorn을 기반으로 하여 Node.js, Go와 견줄 만큼 빠른 성능을 발휘합니다.  
- **자동 문서화**: OpenAPI 표준을 지원하며, `/docs`(Swagger UI)와 `/redoc`(ReDoc) 경로에서 자동으로 API 문서를 확인할 수 있습니다.  
- **데이터 검증**: Pydantic을 통해 요청과 응답 데이터의 구조를 정의하고 자동 검증합니다.  
- **간결한 코드**: Flask와 유사하지만 더 직관적이며, 타입 힌트를 활용해 IDE 자동완성 및 문서화에 강력한 장점을 가집니다.  

---

## 2. 기본 구조
FastAPI 애플리케이션은 크게 다음과 같은 구조를 가집니다.

1. **FastAPI 인스턴스 생성**  
   - `app = FastAPI()`를 통해 애플리케이션 객체를 생성합니다.  
   - 이 객체는 라우팅, 미들웨어, 이벤트 핸들러 등을 관리하는 중심 역할을 합니다.  

2. **라우트 정의**  
   - 특정 URL 경로와 HTTP 메서드를 매핑하여 요청을 처리하는 함수를 등록합니다.  
   - 이때 사용하는 것이 바로 **데코레이터**입니다.  

3. **실행**  
   - `uvicorn main:app --reload` 명령어로 실행합니다.  
   - `main`은 파일 이름, `app`은 FastAPI 인스턴스 이름을 의미합니다.  

---

## 3. 데코레이터 API 종류별 설명

FastAPI에서 가장 중요한 개념 중 하나가 **데코레이터 기반 라우팅**입니다.  
데코레이터는 Python 문법 요소로, 함수에 특정 기능을 덧입히는 역할을 합니다.  
FastAPI에서는 HTTP 메서드(GET, POST, PUT, DELETE 등)에 해당하는 데코레이터를 제공하여 RESTful API를 쉽게 구현할 수 있습니다.  

아래는 주요 데코레이터 종류와 그 의미를 상세히 설명한 내용입니다.

---

### 🔹 `@app.get(path)`
- **GET 요청 처리**  
- 주로 **데이터 조회(Read)** 용도로 사용됩니다.  
- 브라우저에서 URL을 직접 입력하거나, API 클라이언트가 GET 요청을 보낼 때 실행됩니다.  
- 응답은 JSON 형식으로 반환하는 경우가 많습니다.  
- 예: 특정 사용자 정보 조회, 게시글 목록 가져오기  

---

### 🔹 `@app.post(path)`
- **POST 요청 처리**  
- 주로 **데이터 생성(Create)** 용도로 사용됩니다.  
- 요청 본문(body)에 JSON, Form 데이터 등을 포함하여 서버로 전송합니다.  
- 서버는 이를 받아 새로운 리소스를 생성하고 응답을 반환합니다.  
- 예: 회원가입, 게시글 작성, 데이터 업로드  

---

### 🔹 `@app.put(path)`
- **PUT 요청 처리**  
- 기존 데이터를 **전체 수정(Update)**할 때 사용됩니다.  
- 클라이언트는 수정할 객체의 모든 필드를 포함한 데이터를 서버에 전달하고, 서버는 기존 객체를 완전히 교체합니다.  
- 예: 사용자 프로필 전체 수정, 게시글 전체 업데이트  

---

### 🔹 `@app.patch(path)`
- **PATCH 요청 처리**  
- 기존 데이터의 **일부 수정(Partial Update)**에 사용됩니다.  
- PUT과 달리 필요한 필드만 전달할 수 있으며, 서버는 해당 필드만 업데이트합니다.  
- 예: 사용자 닉네임만 변경, 게시글 제목만 수정  

---

### 🔹 `@app.delete(path)`
- **DELETE 요청 처리**  
- 특정 리소스를 **삭제(Delete)**할 때 사용됩니다.  
- 클라이언트가 삭제 요청을 보내면 서버는 해당 리소스를 제거하고 성공 여부를 반환합니다.  
- 예: 게시글 삭제, 사용자 계정 삭제  

---

### 🔹 `@app.options(path)`
- **OPTIONS 요청 처리**  
- 클라이언트가 서버의 지원 메서드, CORS 정책 등을 확인할 때 사용됩니다.  
- 주로 브라우저가 자동으로 실행하여 서버가 어떤 HTTP 메서드를 허용하는지 확인합니다.  
- 예: CORS 설정 확인  

---

### 🔹 `@app.head(path)`
- **HEAD 요청 처리**  
- GET 요청과 유사하지만 **본문(body) 없이 헤더만 반환**합니다.  
- 리소스의 존재 여부나 메타데이터를 확인할 때 활용됩니다.  
- 예: 파일 존재 여부 확인, 응답 크기 확인  

---

## 4. 데코레이터와 RESTful API의 관계
FastAPI의 데코레이터는 RESTful API의 CRUD 동작을 그대로 반영합니다.

- **Create** → `@app.post`  
- **Read** → `@app.get`  
- **Update** → `@app.put`, `@app.patch`  
- **Delete** → `@app.delete`  

이 구조 덕분에 FastAPI는 RESTful API를 직관적으로 설계할 수 있으며, 자동 문서화 기능을 통해 API 사용법을 쉽게 공유할 수 있습니다.

---

## 5. 확장된 데코레이터 활용
FastAPI는 기본적인 HTTP 메서드 외에도 다양한 기능을 데코레이터로 제공합니다.

- **미들웨어 등록**: `@app.middleware("http")` → 요청/응답 처리 과정에 공통 로직 삽입  
- **이벤트 핸들러 등록**: `@app.on_event("startup")`, `@app.on_event("shutdown")` → 서버 시작/종료 시 실행할 로직 정의  
- **경로 매개변수(Path Parameter)**: 데코레이터에 `{}`를 사용하여 동적 경로 처리  
- **쿼리 매개변수(Query Parameter)**: 함수 인자로 정의하여 자동 검증 및 문서화  

---

## 6. 문서화와 데코레이터의 연결
FastAPI의 강력한 기능 중 하나는 **자동 문서화**입니다.  
데코레이터로 정의된 모든 엔드포인트는 OpenAPI 스펙에 따라 자동으로 문서화되며, `/docs`와 `/redoc`에서 확인할 수 있습니다.  
이는 개발자와 클라이언트가 API를 쉽게 이해하고 테스트할 수 있도록 돕습니다.

# 📑 최종 정리

| 데코레이터 | 주요 목적 | 특징 |
|------------|-----------|------|
| `@app.get` | 조회(Read) | URL 접근 시 기본 응답 |
| `@app.post` | 생성(Create) | 요청 본문 데이터 처리 |
| `@app.put` | 전체 수정(Update) | 기존 객체를 완전히 교체 |
| `@app.patch` | 부분 수정(Update) | 일부 필드만 수정 가능 |
| `@app.delete` | 삭제(Delete) | 리소스 제거 |
| `@app.options` | 옵션 확인 | 서버 지원 메서드 확인 |
| `@app.head` | 헤더 확인 | 본문 없이 헤더만 반환 |
