## 전처리

### 핵심 결정사항

1. **필드 선택**: `ko`와 `mt` 사용
2. **특수문자 `>`**: 제거
3. **구두점**: 유지 (`.`, `?`, `!`, `,` 등)
4. **공백**: 불필요한 공백만 제거 (연속 공백 등)

---

## 한글 전처리 (ko 필드)

### 1. 텍스트 정제

#### 1.1. 특수문자 처리

**제거할 것**
```
'>': 제거
```

**유지할 것**
```
'.': 마침표 (문장 종료)
'?': 물음표 (의문문)
'!': 느낌표 (감탄문)
',': 쉼표 (절 구분)
```

**처리 예시**
```
입력: ">아, 진짜요?"
출력: "아, 진짜요?"
```

---

#### 1.2. 공백 정규화

**제거할 공백**

**연속 공백**
```
"안녕   하세요" -> "안녕 하세요"
"여러개    공백" -> "여러개 공백"
```

**앞뒤 공백 (strip)**
```
"  안녕하세요  " -> "안녕하세요"
```

**탭, 개행 등**
```
"안녕\t하세요" -> "안녕 하세요"
"안녕\n하세요" -> "안녕 하세요"
```

---

**유지할 공백**

**단어 사이 공백**
```
"안녕 하세요" -> 유지
"그래서 이것을 보면서" -> 유지
```

**구두점 주변 공백**
```
"아, 진짜요?" -> 유지 (쉼표 뒤 공백 자연스러움)
```

---

#### 1.3. Unicode 정규화

**적용: NFC**
```
조합 문자 -> 완성형
일관된 표현 보장
```

---

### 2. 필터링

#### 2.1. 빈 값 제거
```
ko가 None, 빈 문자열, 공백만 있는 경우 -> 제거
```

#### 2.2. 길이 필터링
```
최소: 1글자 이상 (전처리 후 기준)
최대: 통계 분석 후 결정 (99 percentile)
```

#### 2.3. word_ratio 필터링
```
범위: 0.3 ~ 5.0
극단값 제거
```

#### 2.4. 중복 제거
```
완전히 동일한 ko 텍스트: 제거
```

---

## 영문 전처리 (mt 필드)

### 1. 텍스트 정제

#### 1.1. 대소문자 통일

**소문자 변환**
```
"Oh, really?" -> "oh, really?"
"I think Mino will do it." -> "i think mino will do it."
```

---

#### 1.2. 특수문자 처리

**mt 필드는 이미 `>` 없음**
```
확인 완료: "Oh, really?" (> 없음)
```

**유지할 구두점**
```
'.', '?', '!', ','
```

**아포스트로피 유지**
```
"don't" -> "don't" (그대로)
"it's" -> "it's" (그대로)
```

---

#### 1.3. 공백 정규화

**한글과 동일**
```
연속 공백 제거
앞뒤 공백 제거
탭/개행 -> 공백
```

---

#### 1.4. Unicode 정규화

**적용: NFC**
```
한글과 동일하게 NFC 적용
악센트 문자 대비 (café 등)
```

---

### 2. 필터링

**한글과 동일 기준 적용**
```
빈 값 제거
길이 필터링
word_ratio 필터링
중복 제거
```

## 구두점 유지 이유 (동의)

### 번역에서 구두점의 중요성

**문장 종류 구분**
```
한글: "진짜요?" vs "진짜요."
영문: "really?" vs "really."

의문문 vs 평서문 구분 필수
```

**문장 구조**
```
한글: "채소와 토핑이 어우러지며, 입안 가득..."
영문: "vegetables and soft toppings, in your mouth..."

쉼표가 절 구분
```

**감정/뉘앙스**
```
"정말이에요!" vs "정말이에요."
"really!" vs "really."

느낌표가 강조 표현
```

## 특수한 문자 처리 전략

### 유지할 문자

**기본 구두점**
```
. (마침표)
? (물음표)
! (느낌표)
, (쉼표)
```

**영어 특수문자**
```
' (아포스트로피): don't, it's 등
- (하이픈): well-known 등
```

**숫자**
```
0-9: 날짜, 수량 등에 필요
```

---

### 제거할 문자

**대화 표시**
```
> : 제거 확정
```

**잠재적 제거 대상** (데이터 확인 후 결정)
```
" (따옴표): 있다면?
( ) (괄호): 있다면?
: (콜론): 있다면?
; (세미콜론): 있다면?
```

**확인 필요**
- 실제 데이터에 위 문자들이 있는지?
- 있다면 빈도와 용도는?

## 공백 처리 상세

### 정규화할 공백

**공백 유형**
```
' ' (스페이스): 일반 공백
'\t' (탭): 공백으로 변환
'\n' (개행): 공백으로 변환
'\r' (캐리지 리턴): 제거 또는 공백으로
```

---

### 처리 규칙

**연속 공백 통합**
```
정규식: r'\s+' -> ' '

"안녕    하세요" -> "안녕 하세요"
"hello  world" -> "hello world"
```

**앞뒤 제거 (strip)**
```
"  text  " -> "text"
```

**구두점 주변 공백** (현재: 그대로 유지)
```
"안녕 , 세계" -> "안녕 , 세계" (유지)
"hello , world" -> "hello , world" (유지)
```

**이유**: 
- 데이터 원본 보존
- 구두점 주변 공백도 의미 있을 수 있음
- 과도한 정제 지양

## 예시: 전처리 전후

### 샘플 1

**입력**
```json
{
  "ko": ">아, 진짜요?",
  "mt": "Oh, really?"
}
```

**전처리 후**
```
ko: "아, 진짜요?"
mt: "oh, really?"
```

---

### 샘플 2

**입력**
```json
{
  "ko": ">민호가   할 것 같아서.  ",
  "mt": "I  think Mino will do it."
}
```

**전처리 후**
```
ko: "민호가 할 것 같아서."
mt: "i think mino will do it."
```

---

### 샘플 3

**입력**
```json
{
  "ko": "그래서 이것을 보면서 요구하는 바에 찬찬히 맞춰가는 것도 한 방법이에요.",
  "mt": "So looking at this and keeping up with the demands is one way."
}
```

**전처리 후**
```
ko: "그래서 이것을 보면서 요구하는 바에 찬찬히 맞춰가는 것도 한 방법이에요."
mt: "so looking at this and keeping up with the demands is one way."
```
